# M6: Sync (push, pull, conflicts) 📱

Branch `m6-sync`, stacked on `m5-features` (PR #6). Goal: a phone can work offline for days and sync safely.

## What is in this PR

- **Tenant tables:** `ProjectSyncState` (per-project seq, locked FOR UPDATE), `ChangeLog`
  (gap-free, `UNIQUE(project, seq)`), `AppliedChange` (idempotency on `change_id`), `SyncCursor`
  (per device: cursor and support metrics), `Conflict` (both payloads, status, resolution).
- **Changelog on every write:** `write_feature`, delete, restore and review append a changelog row
  under the project lock, so web edits and reviews reach the next pull.
- **`POST /sync/push`:** up to 200 changes, gzip accepted, one transaction per project, per-change
  savepoints, results `accepted | merged | conflict | rejected | duplicate` following the conflict
  table in the engineering notes (field-level merge from `FeatureHistory.changed_fields`, delete vs
  edit both ways, create on an existing id, validation failures rejected with per-field errors).
- **`GET /sync/pull`:** latest state per changed feature in seq order, `next_cursor`, `has_more`,
  `config_version`; includes review status and send-back notes; never the raw track.
- **Conflicts:** `GET /conflicts`, `GET /conflicts/{id}`, `POST /conflicts/{id}/resolve`
  (keep server, keep device, merged) with a `merge` history row and a changelog entry.
- **Metrics:** `SyncCursor` counters and durations, `Device.last_sync_at`.
- Contract regenerated (v0.1.1, no shape changes), M4 stubs replaced.

## Summary for Selorm (📱 checkpoint)

- `POST /sync/push` and `GET /sync/pull` are live; shapes are unchanged from v0.1.0 and the mock.
- Keep sending `change_id` (UUIDv7) per outbox row; a replayed batch returns `duplicate` with the
  original `feature {id, version}`. Clear accepted/merged/duplicate rows from the outbox; keep
  `conflict` rows locally (the feature carries the `conflict` flag until a manager resolves it;
  the resolved state arrives in a later pull) and show `rejected` errors to the collector.
- For updates, send `base_version` (the version you pulled) and `changed_fields` (attribute keys plus
  `"geom"`); non-overlapping edits merge server-side (`merged`, new version returned).
- Pull: apply items in order, store `next_cursor` only after applying the page, loop while `has_more`.
  Re-download the bundle when `config_version` changes. `status` / `review_note` carry reviews.
- Gzip the push body with `Content-Encoding: gzip` on slow links.
