# M8: Web app foundation and project setup UI

Branch `m8-web-foundation`, stacked on `m7-attachments` (PR #8). Goal: a non-GIS admin can set up the
pilot project in the browser.

## What is in this PR

- **`apps/web`:** Vite + React 19 + TypeScript (strict), Tailwind 4, TanStack Router and Query,
  React Hook Form + Zod, `@precisecapture/api-client` and `@precisecapture/schema` from the workspace.
- **Auth:** login by email or phone with password, OTP request and verify, localStorage token store
  with the client's single-flight refresh, org switcher, create-your-first-organisation.
- **Shell:** sidebar (Projects, Data, Members, Settings), responsive, toasts, problem-JSON error view.
- **Organisation:** settings (name, slug, country) and org-level capture defaults; members with role
  changes and removal; invitations by email or phone; pending invitations with revoke.
- **Projects:** list; create/edit with the project area drawn on a MapLibre map or uploaded as
  GeoJSON/KML; project-level capture rules; layers table with add-layer (or from a template);
  project members with roles and assigned areas drawn on the map.
- **Layer screen** (tabs): General (name, style; key and geometry fixed); Attributes (drag-and-drop
  builder, every field type, options/named lists with cascading filters, relation picker, expressions
  validated live by the shared evaluator, Import JSON, live phone-sized preview); Capture rules
  (toggles/sliders/locks, 1-2-3-5-10 m streaming, inherited values, shared semantic checks, Import
  JSON); Publish (diff vs current version with breaking type changes highlighted, server dry run,
  publish with warnings, versions, save as template).
- **Tests:** vitest (token store, login errors/OTP switch, form preview vs the shared evaluator) and a
  Playwright flow in CI against the real API.
- Fix in `@precisecapture/api-client`: relative base URLs (dev proxy) now work.

| Criterion | Result | Evidence |
| --- | --- | --- |
| Ben can create the Western North project with the Farmers and Farms layers entirely in the UI | ✅ | `apps/web/e2e/setup.spec.ts`: login → new project (+ project capture rule) → add Farmers (none) and Farms (polygon) → attributes (builder + Import JSON of the pilot schemas) → capture rules → publish both |
| The resulting bundle matches what `seed_pilot` produces | ✅ | Same test: fetches both bundles and asserts identical layer keys, geometry types, schema versions, fields, lists and resolved capture profiles |
| Form preview and validation behave identically to the server | ✅ | `FormPreview.test.tsx` uses the shared evaluator on the Farms schema (relevant hides `other_crop`, `area_ha` = 1.23456 from 12 345.6 m², constraint/required as on the server); the Attributes tab validates expressions with the same `validateExpression` the server's publish uses |
| Playwright e2e covers login → create project → add layer → add attributes → publish | ✅ | `e2e/setup.spec.ts`, run locally and in the API CI job |

Also: `make web-lint` (tsc strict, ESLint, Prettier), `make web-test` (vitest), `pnpm --filter web build`.

## How to try it

```bash
make dev-up api-migrate && (cd apps/api && uv run python manage.py seed_pilot)
make api-run        # :8000
make web-dev        # :5173, log in as manager@pilot.local / pilot-pass-2026
```
