# M2: Accounts, organisations, tenancy, auth

Branch `m2-accounts-tenancy`, stacked on `m1-shared-schema` (merged into `m0-monorepo-dev-env`);
rebase onto `main` once PR #1 merges. Goal: users log in and act inside one organisation at a time,
and the database itself enforces isolation.

## What is in this PR

- **Accounts:** custom `User` (UUIDv7, email and/or E.164 phone with a DB check, argon2, status),
  `Device`, `RefreshToken` (hashed, rotating, families), `OtpCode` (hashed, 10 min, 5 attempts).
- **Organisations:** `Organisation` (slug, plan, `settings.capture_defaults`, `data_destination`
  placeholder), `Membership` (unique per user/org, role, version), `Invitation` (hashed token, 7 days).
- **Tenancy plumbing:** `tenant_context()`, `enable_rls()` migration helper with the `NULLIF` policy
  and FORCE, `TenantModel` with a fail-closed default manager, `TenantAuth` (Ninja auth class setting
  the tenant with `set_config` inside the request transaction), a middleware clearing the contextvar,
  and 11 isolation tests on a test-only tenant table (`SET ROLE pc_app`).
- **Auth endpoints:** `POST /auth/login|refresh|logout|otp/request|otp/verify`, `GET /me`,
  `GET /me/projects` (stub), `POST/GET /devices`, `DELETE /devices/{id}`.
- **Org endpoints:** `POST /orgs`, `GET/PATCH /orgs/{id}`, members list/role/remove,
  invitations create/list/revoke, `GET /invitations/{token}`, `POST /invitations/{token}/accept`.
- **Permissions:** `require_role(request, minimum)`, `can_assign_role()`; project-level checks plug
  in here in M3.
- **Rate limits** on the cache (Redis): login per identifier and IP, OTP per destination and IP.
- **Messaging:** `SmsBackend` interface with a console backend; email via Django (Mailpit in dev).
- **Platform admin:** Django admin at `/platform-admin/` only when `PLATFORM_ADMIN_ENABLED=true`,
  through the `platform` alias.
- `/.well-known/precisecapture` advertises `["password", "otp"]`.

## Notes for Selorm

Nothing to build against yet beyond the auth shape, which M4 publishes with the mock server:
password login (`identifier` = email or phone), OTP request/verify, a 15 minute bearer JWT, a
rotating refresh token (always store the newest one; a replayed old token logs the device out),
`POST /devices` with a client-generated UUIDv7 before a device-bound login, and `X-Org-Id` on every
tenant endpoint.
