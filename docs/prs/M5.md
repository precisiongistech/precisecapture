# M5: Features and spatial computations

Branch `m5-features`, stacked on `m4-contract-v0` (PR #5). Goal: features can be stored, queried and
audited, with all server-side geometry rules.

## What is in this PR

- **Tenant tables** (RLS, picked up by the generic isolation test): `Feature` (client UUIDv7 id,
  geometry CHECK via PostGIS `GeometryType()`, GIST index, computed `area_m2` / `perimeter_m` /
  `length_m` / `centroid` / `centroid_method`, `qa_flags`, soft delete, who/when/which device),
  `FeatureHistory`, `FeatureRelation`, `RawTrack`, `VertexMeta`; global `IdempotencyKey`.
- **`features.services.write_feature()`**, used by the web now and by sync in M6: attribute
  validation against the schema version (every field type, relevant/required/constraint, calculate
  recomputed per the trust table, uniqueness, relation targets), geometry validation against the
  resolved capture profile, PostGIS measures on the geography type, overlap QA, extent/assigned-area
  flags, history and relations in one transaction, optimistic concurrency on `version`.
- **Endpoints:** `GET /layers/{id}/features` (GeoJSON FeatureCollection; bbox, status,
  updated_since, include_deleted, qa_flag, `attr.<key>` filters; cursor pagination),
  `POST /layers/{id}/features`, `GET /features/{id}` (raw track, vertex meta, relations),
  `GET /features/{id}/history`, `PATCH /features/{id}` (base_version / If-Match), `DELETE` (soft),
  `POST .../restore`, `POST .../review` (approve / reject / send back with a note).
- **Tiles:** `tiles_layer()` PostGIS function (SECURITY DEFINER, EXECUTE for pc_tiles) and
  `GET /projects/{id}/tiles/{layer}/{z}/{x}/{y}.mvt` proxied to Martin after the membership check.
- **Idempotency-Key** middleware (24 h replay, mismatch → 422).
- Layer delete refuses once features exist.

## Notes for Selorm

- Attribute storage shapes are now fixed: `group` fields flat, `repeat` as a list of row objects,
  photos/files as lists of attachment UUIDs, `geopoint` as a GeoJSON Point, `relation` as the
  target feature UUID, `yes_no` as `"yes"`/`"no"`. Empty strings become null except for text/barcode.
- The server recomputes `calculate` fields that depend only on attributes or geometry; values from
  `lookup()`, `ghanapost_gps()`, `today()`, `now()` are kept as sent.
- QA flags you may see on a pulled feature: `overlap`, `centroid_fallback`, `invalid_geometry`,
  `outside_extent`, `outside_assigned_area`.
- `GET /features/{id}` is the audit view (raw track, vertex meta); pull (M6) never includes the track.
