# M1: Shared schema package (contract part 1) 📱

Branch `m1-shared-schema`, branched from `m0-monorepo-dev-env` (rebase onto `main` once PR #1 merges).
Goal: a single source of truth for layer attribute schemas and capture profiles, usable from TS (web
and mobile) and Python (server).

## What is in this PR

- **`@precisecapture/schema@0.1.0`** as a real pnpm package: tsup build (ESM + CJS + d.ts), vitest,
  `CHANGELOG.md`, README, generated `src/types.ts` (CI fails when stale).
- **Validators:** Ajv (TS) and jsonschema (Python) over the same three JSON files. Strict mode for the
  server, lenient mode for apps (unknown keys stripped from a copy).
- **Schema tightening (backward compatible):** layer references (`relation.layer`, `snapping.layers`,
  `trace.layers`, `topology.*`) must match the layer key pattern or `self`.
- **Expression language v1:** semantics pinned in `expressions.md`; tokenizer, recursive-descent
  parser and evaluator in TypeScript (`src/expr`) and Python (`common/expr.py`), no `eval`;
  107 shared vectors.
- **Capture profiles:** `capture-profile-resolution.md` pins the level merge, locks and six
  cross-field rules; `resolveCaptureProfile` and `validateCaptureProfileSemantics` in both languages;
  35 shared vectors.
- **`make schema-test`** runs the TS lint/tests and the Python vector tests; CI builds the packages.

## Contract summary for Selorm (mobile)

Package: `@precisecapture/schema@0.1.0` (workspace package; `pnpm add @precisecapture/schema` inside
the monorepo). Read `packages/schema/README.md`, `expressions.md` and `capture-profile-resolution.md`.

- **Validate documents from the server in lenient mode:** `validateLayerSchema(doc, "lenient")`,
  `validateCaptureProfile(doc, "lenient")`. Unknown keys are stripped, so a newer server never breaks
  an older app. Push payloads you build should pass `validatePushRequest(payload)` (strict).
- **Forms:** `evaluate(expr, ctx)` for `relevant`, `required`, `constraint`, `calculate`. The context
  carries `values`, `self`, `repeatItem`, `now`, `today`, `geomAreaM2`, `geomLengthM`, `lookup`,
  `ghanapostGps`. Null rules: `relevant` null → shown; `required`/`constraint` null → not required /
  not violated. `referencedFields(expr)` gives the keys a field depends on (for recalculation).
- **Capture rules:** on the phone call `resolveCaptureProfile(null, null, layerProfileFromBundle,
  collectorToggles)`. The bundle (M3) will already carry the org → project → layer merge, so the phone
  only applies collector toggles. The result keeps `locked` flags: hide a toggle when its object is
  locked. Collector toggles may only change keys inside `modes`, `autoClose`, `snapping`, `trace`,
  `stream`, `gps`, `gps.averaging`, `offsetPoints`.
- **Layer references** in schemas and profiles are layer **keys** (`lyr_farmers`), or `self`. API paths
  and sync payloads use layer UUIDs; the bundle maps key ↔ id.
- **Breaking changes:** none (first version).

## Notes

- `expressions.md` changed the evaluation context: `repeat?: Record<string, unknown>[]` became
  `repeatItem?: Record<string, unknown>` (the current row), and `${repeat.key}` reads a child key across
  rows. Nothing had implemented the old shape.
- The spec's §9 expression list mentions `nearest()`; it stays reserved and is a parse error in v1.
