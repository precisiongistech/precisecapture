# M3: Projects, layers, layer schemas, capture profiles, bundle 📱

Branch `m3-projects-layers`, stacked on `m2-accounts-tenancy` (PR #3). Goal: an admin can
configure the pilot project via the API, and a phone can download everything it needs.

## What is in this PR

- **Tenant tables** (org_id + FORCE RLS in the migration): `Project`, `ProjectMember`, `Layer`,
  `LayerSchemaVersion`, `LayerTemplate`. A generic test discovers every `TenantModel` and proves RLS
  is installed and that org A cannot read or re-home org B's rows as `pc_app`.
- **Projects and members:** CRUD, extent polygon (EPSG:4326, validated), project-level capture
  profile in `settings.capture_profile`, members with roles and assigned areas. Member changes bump
  `Membership.version` and `config_version`.
- **Layers:** create/list/order under the project, get/patch/delete, immutable `key` and
  `geometry_type`, capture profile validated on create.
- **Schema draft → publish:** `PUT /layers/{id}/schema`, `POST .../schema/validate` (dry run),
  `POST .../schema/publish` (JSON Schema, expression parsing with the field list, duplicate keys,
  relation targets by key, option lists, safe-widening type check), versions list/get.
- **Capture profile:** `GET/PUT /layers/{id}/capture-profile` returning the resolved
  org → project → layer profile; validated with the JSON Schema and the shared semantic rules.
- **Templates:** save a layer as a template, list, delete, create a layer from a template.
- **Bundle:** `GET /projects/{id}/bundle` with a per-user ETag, `If-None-Match` → 304, and the
  `X-Server-Seq` header (0 until M6). `GET /me/projects` spans organisations.
- **`seed_pilot`:** idempotent demo org, four users, the Western North project, Farmers and Farms
  layers published from `packages/schema/examples`.

## Contract summary for Selorm (📱 checkpoint)

- `GET /me/projects` (bearer only): `[{id, name, status, org_id, org_name, role, config_version}]`.
- `GET /projects/{id}/bundle` with `X-Org-Id`: body `{project, org, my_role, layers[], basemap_packs[],
  config_version, generated_at}`. Each layer has `id` (UUID, use it in sync payloads), `key`
  (used inside schemas and profiles), `geometry_type`, `style`, `schema_version`, `schema`
  (the published attribute document, or null), `lists`, and `capture_profile` already resolved
  org → project → layer (apply collector toggles with `resolveCaptureProfile(null, null, profile, toggles)`).
- Send `If-None-Match` with the last `ETag`; a 304 means nothing changed for you. Read
  `X-Server-Seq` from the headers (0 for now). Re-download when `config_version` in a pull (M6) moves.
- `GET /layers/{id}/schema/versions/{v}` returns any published version (features record the version
  they were captured with).
- The contract file `contract/openapi.json` is updated; M4 adds examples and the mock server.
